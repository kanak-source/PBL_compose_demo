# PBL Compose Demo – FastAPI CI/CD with Docker

This project demonstrates containerization, automated API testing, Docker Compose, and a CI/CD pipeline using GitHub Actions and Docker Hub.

## Project Overview

The project contains a simple **Student API** developed using **FastAPI**.

The application provides endpoints to:

- Check whether the application is running
- Check application health
- Retrieve student data

The application is containerized using Docker and can also be started using Docker Compose. Automated API tests are executed before the Docker image is built and pushed to Docker Hub through GitHub Actions.

## API Endpoints

### Root Endpoint

```http
GET /
```

Returns basic information about the application.

Example response:

```json
{
  "application": "Student API",
  "framework": "FastAPI",
  "status": "running"
}
```

### Health Check

```http
GET /health
```

Example response:

```json
{
  "status": "healthy"
}
```

### Students

```http
GET /students
```

Returns the available student records.

## Run the Application Locally

Create a virtual environment:

```bash
python3 -m venv venv
```

Activate it on macOS/Linux:

```bash
source venv/bin/activate
```

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

Start the FastAPI application:

```bash
python -m uvicorn main:app --reload
```

The API will be available at:

```text
http://localhost:8000
```

FastAPI Swagger documentation:

```text
http://localhost:8000/docs
```

## Docker

Build the Docker image:

```bash
docker build -t student-api:v0.1 .
```

Run the container:

```bash
docker run --rm -p 8000:8000 student-api:v0.1
```

Test the health endpoint:

```bash
curl http://localhost:8000/health
```

## Docker Compose

Build and start the application:

```bash
docker compose up -d --build
```

Check the running service:

```bash
docker compose ps
```

Test the API:

```bash
curl http://localhost:8000/health
curl http://localhost:8000/students
```

Stop the services:

```bash
docker compose down
```

## Automated Testing

The `automationTesting.py` script automatically tests the API routes.

Run:

```bash
python automationTesting.py
```

Expected result:

```text
GET / -> 200
PASSED: /
GET /health -> 200
PASSED: /health
GET /students -> 200
PASSED: /students

All API tests passed successfully!
```

A successful test execution exits with status code `0`, while a failed test exits with status code `1`. This allows GitHub Actions to stop the CI/CD pipeline when API tests fail.

## CI/CD Pipeline

GitHub Actions is configured using:

```text
.github/workflows/ActionsYaml.yaml
```

The pipeline follows this process:

```text
Developer
    ↓
Git Push
    ↓
GitHub Actions
    ↓
Checkout Repository
    ↓
Set Up Python
    ↓
Install Dependencies
    ↓
Start FastAPI Application
    ↓
Run automationTesting.py
    ↓
Tests Pass
    ↓
Login to Docker Hub
    ↓
Build Docker Image
    ↓
Push Docker Image to Docker Hub
```

If automated testing fails, the Docker build and push steps are not executed.

## GitHub Actions Secrets

The following repository secrets are configured in GitHub:

```text
DOCKERUSERNAME
DOCKERTOKEN
```

The Docker Hub access token is stored securely using GitHub Actions Secrets and is not committed to the repository.

## Request Logging

The FastAPI application includes middleware for request logging.

Example:

```text
method=GET path=/health status=200 duration_ms=2.36
method=GET path=/students status=200 duration_ms=4.99
```

This provides basic observability by recording the HTTP method, requested path, response status, and request duration.
